## Классификация языка SQL

| Класс | Назначение | Примеры в MySQL |
|-------|------------|-----------------|
| **DDL** (Data Definition) | Схема: объекты и их структура | `CREATE` / `ALTER` / `DROP` DATABASE, TABLE, INDEX; `TRUNCATE` |
| **DML** (Data Manipulation) | Содержимое | `SELECT`, `INSERT`, `UPDATE`, `DELETE` |
| **DCL** (Control) | Доступ | `GRANT`, `REVOKE` |
| **TCL** (Transaction) | Границы изменений | `START TRANSACTION`, `COMMIT`, `ROLLBACK` |
| **Служебные** | Интроспекция | `SHOW`, `DESCRIBE`, `EXPLAIN` |

**Когда DDL:** новый домен, изменение модели, индексы под запросы, миграции. В проде — миграционные скрипты, оценка блокировок (`ALGORITHM`, online DDL в новых версиях).

**Когда DML:** повседневная работа приложения, отчёты, пакетные правки данных.

**Когда не путать:** `TRUNCATE` — DDL (быстрое опустошение, сброс AUTO_INCREMENT); `DELETE` без WHERE — DML (построчно, транзакционно в InnoDB).

## Жизненный цикл данных (Learning MySQL)

```
Требования → ER-модель (conceptual) → SQL-схема (logical) → CREATE TABLE (physical)
                ↓
         INSERT / SELECT / UPDATE / DELETE
                ↓
         ALTER / индексы / резервные копии (гл. 10)
```

Три стадии проектирования (гл. 4): **requirements analysis** → **conceptual (ER)** → **logical (таблицы в СУБД)**.

## Нормализация и ER-модель

Книга не вводит явные 1NF/2NF/3NF, а даёт **нормализацию через декомпозицию сущностей**:

| Идея | Практика |
|------|----------|
| Убрать повторяющиеся группы | Отдельная таблица `Student_Details` vs дубли имён в каждой строке оценок |
| Идентификатор сущности | **Primary key** — NOT NULL, уникален; surrogate id (student_id, product_id) когда нет естественного ключа |
| Связи | 1:1, 1:N, M:N; на логическом уровне M:N → **junction table** |
| Foreign key | PK владеющей сущности в таблице зависимой стороны (1:N — FK на стороне N) |
| Слабые сущности | PK = свой id + FK владельца (напр. track = `{artist_id, album_id, track_id}`) |
| Ключи-кандидаты | email уникален, но multivalued телефоны — осторожно с «удобными» ключами |
| Денормализация | Осознанно для отчётов/кэша; сначала нормальная схема, потом точечное денорм |

**Правила маппинга ER → таблицы (кратко):**
- Сущность → таблица + атрибуты.
- 1:1 — FK с одной стороны (или объединение если тесная связь).
- 1:N — FK со стороны N.
- M:N — таблица связи с PK из пары FK (иногда + атрибуты связи, напр. timestamp продажи).

Инструмент: **MySQL Workbench** — ER → forward engineering в схему.

## DDL: базы и таблицы

| Операция | Когда | Заметки MySQL |
|----------|-------|----------------|
| `CREATE DATABASE` | Новый bounded context / tenant | Кодировка `DEFAULT CHARSET` |
| `USE db` | Перед DDL/DML в сессии | |
| `CREATE TABLE` | Новая сущность | Имя столбца: до 64 символов; `ENGINE=InnoDB` по умолчанию в современных установках |
| `ALTER TABLE` | Новый столбец, индекс, тип | Книга: осторожно на больших таблицах |
| `DROP DATABASE` / `DROP TABLE` | Тест, откат миграции | Необратимо без бэкапа |
| `SHOW CREATE TABLE` | Документирование, diff | Точная DDL копия |

Секции `CREATE TABLE`:
1. Имя таблицы.
2. Список столбцов: `name type [NOT NULL | NULL] [DEFAULT …]`.
3. Ограничения: `PRIMARY KEY`, `UNIQUE`, `KEY`, `FOREIGN KEY` (InnoDB).

**AUTO_INCREMENT** — суррогатные ключи; один такой столбец на таблицу.

## Типы столбцов: когда что

### Числа (частые)

| Тип | Когда | Оговорки |
|-----|-------|----------|
| **INT** / **INTEGER** | Счётчики, id, целые | UNSIGNED, `ZEROFILL` (display width не ограничивает величину) |
| **SMALLINT**, **TINYINT**, **BIGINT** | Диапазон поменьше/больше | Выбор по кардинальности |
| **DECIMAL(p,s)** | Деньги, фиксированная точность | Предпочтительнее FLOAT для денег; хранение binary с 5.0.3+ |

### Дата и время

| Тип | Когда | Оговорки |
|-----|-------|----------|
| **DATE** | Только дата | Диапазон 1000–9999; invalid → `0000-00-00` (строгость зависит от sql_mode) |
| **TIME** | Длительности, не «момент» | До 838:59:59 |
| **DATETIME** | Календарный момент без TZ | Без авто-update |
| **TIMESTAMP** | Авто `ON UPDATE`, ограниченный диапазон (до ~2037) | Одна колонка с auto-update на таблицу; NULL → current time (поведение зависит от позиции колонки) |
| **YEAR** | Год | Узкий use-case |

### Строки и бинарные

| Тип | Когда | Оговорки |
|-----|-------|----------|
| **CHAR(n)** | Фиксированная длина, коды | Паддинг пробелами |
| **VARCHAR(n)** | Переменная длина до n | Trailing spaces; 1–2 байта длины |
| **TEXT** / **BLOB** | Длинный текст / бинарь | TINY/MEDIUM/LONG; индекс только на префиксе |
| **ENUM** | Закрытый набор значений | Хранится компактно; смена списка — DDL |
| **SET** | Множественный выбор из набора | Реже ENUM |

### Выбор типа (эвристики из книги)

- Целые id → **INT** или **BIGINT** UNSIGNED.
- Имена, заголовки → **VARCHAR** адекватной длины (не MAX «на всякий случай» без нужды).
