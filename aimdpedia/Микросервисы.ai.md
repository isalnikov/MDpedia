## TL;DR (Core Vector)
Микросервисы — архитектурный стиль, где приложение состоит из небольших независимых сервисов, каждая из которых отвечает за свою бизнес-возможность, имеет собственную БД и общается через API (HTTP/gRPC/Message Queue).

## Определение (Definition)
Микросервисная архитектура — стиль проектирования, разбивающий монолитное приложение на набор мелких, слабо связанных сервисов, каждый из которых развёртывается независимо и владеет своей моделью данных.

## Ключевые факты (Facts)
- Термин: James Lewis & Martin Fowler (2014)
- Принципы: Single Responsibility, Independent Deployability, Decentralized Data Management
- Коммуникация: REST/HTTP, gRPC, Async (Kafka, RabbitMQ)
- Service Discovery: Eureka, Consul — динамическая адресация сервисов
- API Gateway: Spring Cloud Gateway, Kong — единая точка входа
- Circuit Breaker: Resilience4j — защита от каскадных отказов
- Distributed Tracing: OpenTelemetry, Jaeger, Zipkin — трейсинг запросов
- Deployment: Docker + Kubernetes — оркестрация контейнеров

## Ядро для ИИ (Embedding Target)
Монолит vs Микросервисы:
- Монолит: единая кодовая база, одна БД, один deploy — просто, но масштабирование только целиком
- Микросервисы: независимые сервисы, свои БД, независимый deploy — сложно, но масштабируется по компонентам

Паттерны:
- Database per Service: каждый сервис владеет своей БД (нет shared database)
- Saga: распределённые транзакции через цепочку локальных транзакций + compensation
- CQRS: разделение команд (write) и запросов (read) — разные модели
- Event Sourcing: состояние = последовательность событий, не текущий snapshot
- API Composition: агрегация данных из нескольких сервисов в один ответ

Failure handling:
- Circuit Breaker: Fail → Open (reject fast) → Half-Open (probe) → Closed (recover)
- Retry with backoff: повтор с экспоненциальной задержкой
- Bulkhead: изоляция ресурсов (thread pool per service)
- Fallback: деградация функциональности при отказе

## Применение / Практическое использование
- Spring Cloud: Eureka (discovery), Gateway, Config Server, Sleuth (tracing)
- Kubernetes: Service, Deployment, Ingress, ConfigMap, Secrets
- Service Mesh: Istio, Linkerd — sidecar proxy, traffic management
- Observability: Prometheus (metrics) + Grafana (dashboards) + Jaeger (tracing)
- CI/CD: GitOps (ArgoCD) — deployment из git-репозитория

## Противоречия/Нюансы (Caveats)
- «Начинай с микросервисов» — ошибка: начни с модульного монолита, раздели когда нужно
- Distributed monolith: микросервисы с сильной связностью — худшее из двух миров
- Сложность оперирования: 10 сервисов = 10x мониторинг, логи, деплой
- Distributed transactions: нет ACROSS — eventual consistency, Saga pattern
- Network latency: синхронные вызовы (HTTP) создают цепочки задержек
